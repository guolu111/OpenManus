问题 1：原生重试策略缺少配额耗尽、每日次数封顶的识别逻辑，谷歌中转存在日调用上限，单纯指数退避只会无限重试浪费时间，不会自动触发模型轮转切换备用通道。
问题 3：配置驱动模型仅支持 API 客户端，没有纳入 Chrome 网页桥接模型（9333 端口三标签中转），TOML 无法统一管理网页版豆包 / 千问国际版 / 智谱作为备选模型池。
问题 4：原始动态上下文窗口只根据模型上限调整长度，没有区分跑批任务类型，金庸小说长文本解析场景缺少独立专属压缩策略。
问题 5：重试失败终止后缺少自愈分支，不会自动调用notify_feishu推送告警，也不会触发任务断点保存，长时间跑批遇到限流中断直接丢失进度。
