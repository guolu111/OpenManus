# OpenManus 工具分类管理框架（2026-09-06）

> 参照 Hierarchical Tool Organization 最佳实践：按大类别分组，减少每次调用的决策空间。
> 新增工具时必须归入以下某一分类，不允许散放。

## 六大分类总览

```
┌─────────────────────────────────────────────────────────────────┐
│                    OpenManus 工具金字塔                           │
├─────────────────────────────────────────────────────────────────┤
│  1. 核心执行类 Core Execution    ← 基础操作能力（4个）            │
│  2. 深度思考类 Deep Thinking    ← 多模型协同思考（5个）            │
│  3. 浏览搜索类 Browser & Search ← 信息获取（3个+MCP）             │
│  4. 跑批自愈类 Batch & Healing  ← 业务专用（3个）                 │
│  5. 监控通知类 Monitoring       ← 可观测性（3个）                 │
│  6. 系统控制类 System Control   ← MCP外部工具（动态）             │
└─────────────────────────────────────────────────────────────────┘
```

---

## 1. 核心执行类（Core Execution）

> 基础操作能力，所有任务都可能用到。稳定、低风险。

| 工具名 | 功能 | 风险等级 |
|---|---|---|
| `PythonExecute` | 执行Python代码（计算/数据处理/自动化） | 中 |
| `StrReplaceEditor` | 文件读写编辑（替换/插入/删除） | 中 |
| `AskHuman` | 询问用户获取输入 | 低 |
| `Terminate` | 结束任务 | 低 |

**规则**：核心类工具不依赖外部API，纯本地执行，是所有任务的基础。

---

## 2. 深度思考类（Deep Thinking）

> 多模型协同思考，粗活外包+深度验证。这是我们的核心竞争力。

| 工具名 | 功能 | 模型 | 适用场景 |
|---|---|---|---|
| `AskTag` | 3标签网页版深度思考/交叉验证 | 豆包+千问国际版+智谱清言 | 复杂推理/多模型对比/最终决策 |
| `ZhipuHelper` | 智谱GLM API | free=glm-4-flash(免费) / air=glm-4.5-air(收费) | 翻译/格式整理/监督/初稿/批量粗活 |
| `SiliconflowHelper` | 硅基GLM-4-9B | GLM-4-9B(免费) | 纯JSON/搬运/去重/简单分类 |
| `AskEnhancer` | 提问增强 | 调用3标签前使用 | 模糊提问→结构化四要素 |
| `OptimizePlansTool` | 方案三标签深度优化 | 拆分→3标签→汇总 | 方案改进/深度定制 |

**分工铁律**：
- 你（统帅）只做决策，粗活一律外包给 ZhipuHelper / SiliconflowHelper
- 复杂推理用 AskTag 交叉验证
- 禁止反分工：不要把复杂决策丢给小模型

---

## 3. 浏览搜索类（Browser & Search）

> 信息获取，遇到代码/功能问题优先搜评论区。

| 工具名 | 功能 | 优先级 |
|---|---|---|
| `CommentSearch` | 评论区搜索（GitHub Issues/Stack Overflow/掘金/CSDN） | P0 代码问题优先 |
| `WebSearch` | 通用联网搜索（百度/必应/DuckDuckGo/谷歌） | P1 通用信息 |
| `Browser Use (MCP)` | 浏览器操作（导航/点击/输入/截图/下载） | P2 需要交互时 |

**规则**：
- 代码/功能/报错问题 → 先用 CommentSearch 搜评论区成熟方案
- 通用信息 → WebSearch
- 需要登录态/交互操作 → Browser Use
- 搜索摘要不是有效来源，必须访问原始页面

---

## 4. 跑批自愈类（Batch & Self-healing）

> 业务专用工具，金庸连载跑批核心链路。

| 工具名 | 功能 | 触发场景 |
|---|---|---|
| `BatchRun` | 金庸连载章节跑批（四API+3标签协同，内置自愈+断点续跑） | 用户要求跑批时 |
| `BridgeHealth` | 3标签桥接自愈（诊断8010端口+3标签连通性，异常自动重启） | 标签异常时自动调用 |
| `VoiceCorrect` | 语音纠错（L1固定词对+L2拼音模糊匹配，纯本地不耗API） | 用户语音输入后 |

**规则**：
- 跑批必须用 BatchRun，禁止用 PythonExecute 直接跑批脚本
- 标签异常先 BridgeHealth(check) → 确认异常后 BridgeHealth(restart)
- BridgeHealth 只处理 bridge 进程，绝不碰 Chrome/任务看板/守护进程

---

## 5. 监控通知类（Monitoring & Notification）

> 可观测性，任务关键节点必须更新状态。

| 工具名 | 功能 | 调用时机 |
|---|---|---|
| `StatusMonitor` | 实时状态监控（更新/查询任务状态，关键节点自动记录） | 任务开始/每步完成/完成/出错 |
| `UsageMonitor` | API用量监控（各通道今日调用次数/剩余额度） | 任务开始/结束/告警阈值触发 |
| `NotifyFeishu` | 飞书推送（跑批完成/出错自动推送到用户手机） | 任务开始/完成/出错/告警 |

**规则**：
- 任务开始必须同时调用：StatusMonitor(update) + UsageMonitor(all) + NotifyFeishu(开始)
- 任务完成必须同时调用：StatusMonitor(completed) + UsageMonitor(all) + NotifyFeishu(完成)
- 出错必须：StatusMonitor(error) + NotifyFeishu(错误) + 尝试自愈
- API告警阈值：gcli超800/950、智谱4.5-air超1000万/1200万、任何通道连续3次失败

---

## 6. 系统控制类（System Control）

> MCP动态连接的外部工具，按需加载。

| 工具来源 | 功能 | 连接方式 |
|---|---|---|
| Browser Use CLI 3.0 | 浏览器自动化（Playwright） | MCP stdio |
| 其他MCP服务器 | 按config.toml配置动态加载 | MCP sse/stdio |

**规则**：MCP工具动态注册，不硬编码在工具列表中。

## 工具注册代码结构

```python
# app/agent/manus.py 中的分类注册（建议重构为）

# === 1. 核心执行类 ===
core_tools = [PythonExecute(), StrReplaceEditor(), AskHuman(), Terminate()]

# === 2. 深度思考类 ===
thinking_tools = [
    AskTag(),           # 3标签深度思考
    ZhipuHelper(),      # 智谱粗活
    SiliconflowHelper(),# 硅基粗活
    AskEnhancer(),      # 提问增强
    OptimizePlansTool(),# 方案优化
]

# === 3. 浏览搜索类 ===
search_tools = [WebSearch(), CommentSearch()]  # Browser Use走MCP

# === 4. 跑批自愈类 ===
batch_tools = [BatchRun(), BridgeHealth(), VoiceCorrect()]

# === 5. 监控通知类 ===
monitor_tools = [StatusMonitor(), UsageMonitor(), NotifyFeishu()]

# 合并注册
available_tools = ToolCollection(
    *core_tools, *thinking_tools, *search_tools,
    *batch_tools, *monitor_tools
)
```

## 新增工具流程

1. 确定工具属于哪个分类（6选1）
2. 在对应分类的工具文件中实现（app/tool/ 下按分类建子目录）
3. 在 manus.py 对应分类列表中注册
4. 更新本文档的分类表格
5. 测试工具可用性

## 工具去重原则

- 功能重复的工具合并，不保留多个实现
- 简单功能优先用现有工具组合实现，不新建工具
- 新建工具前先查本文档确认没有同类工具
