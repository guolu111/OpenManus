二、遇到的核心问题 & 解决方案（时间线）
----------------------------------------------------------------------
【问题1】multi_bridge(8010) 内部 context 失联 → HTTP 调三标签全部40s超时
  - 现象：/v1/chat/completions 三标签超时，但日志显示豆包22:37刚成功回复
  - 诊断：9333 CDP直连显示三标签页都健康 → 是 multi_bridge 进程内部
          playwright context 与浏览器失联，非浏览器问题
  - 解决：遵守"multi_bridge常驻不动"铁律，未杀它；
          改用裸 playwright 直接 CDP 连接 9333（绕开 multi_bridge）

【问题2】browser-use 本地 launch 启动即卡死
  - 现象：BrowserSession(headless=True, user_data_dir=.bu_profile) 卡在 "starting..."
  - 根因链：①ProcessSingleton锁文件冲突 ②extra_browser_args非合法参数
           ③疑似 IPv4/IPv6 localhost 解析
  - 解决：弃用 browser-use 本地 launch 路径，
          改用裸 playwright launch_persistent_context（已验证登录态100%有效）

【问题3】browser-use 经 CDP 连 9333 有坑
  - get_element_by_prompt 需 LLM（报 ValueError）；page.press 签名差异
  - 解决：最终不用 browser-use 封装，写独立 CDP 问答引擎 tag_ask_cdp.py

【问题4】页面输入用 evaluate 设置 innerText 无效
  - 现象：发送不成功/超时
  - 解决：必须用 locator.fill + press("Enter")（实测对比确认）

【问题5】OpenManus agent 反复调用工具 → 并发抢浏览器 → 全部超时
  - 现象：最强大脑跑批时，多个 run_ch21_cdp.py/tag_ask_cdp.py 实例并发，
         浏览器标签被并发抢占，出现 210s 超时、回复为空
  - 根因：OpenManus 作为 agent 会自主决策反复调工具（本性），
         且旧实例（最强大脑触发的子进程）未被终止
  - 解决：①手动停止全部残留进程（保留常驻铁律进程）
          ②commander_batch.py 加防重入锁（.batch_lock）
          ③run_ch21_cdp.py 改为"追加+跳过已有天数"模式（不覆盖已有成果）

【问题6】gcli 用量铁律（用户最关心"真实调用"）
  - 现象：之前用户发现"1000次一条没用，全靠角色扮演"
  - 解决：本次 gcli_commander.py 真实调用 gcli API（https://gcli.ggchan.dev），
         每次调用写用量台账 gcli_usage.jsonl（ts/model/tokens），
         --ask 验证成功（gemini-2.5-flash-lite 返回分配方案，5.5s，224+343 tokens）

六、方案评估：需改进/需修改的地方
----------------------------------------------------------------------
【需改进1】OpenManus agent 直跑批会并发（最重要）
  - 问题：agent 本性反复调工具 → 多个实例并发抢浏览器 → 超时
  - 建议：不要让 OpenManus 直接连续跑批；
         改为"gcli_commander.py 单次调用跑批 + 最强大脑只做监督/验收"
         （即本次 gcli_commander.py 方案：gcli 动嘴皮子，脚本干活）

【需改进2】tag_ask_cdp reply 返回整页文本
  - 问题：回复含页面残留（时间戳/历史提示词），clean 不彻底
  - 建议：优化 _wait_reply 的 diff 逻辑，精确切分"新增回复"而非整页

【需改进3】豆包偶发超时
  - 问题：并发结束后第一次调用豆包偶发 193s 超时
  - 建议：跑批前对豆包做一次健康检测（发测试消息），失败则先恢复再跑

【需改进4】残留进程清理
  - 问题：并发结束后有残留 run_ch21_cdp/tag_ask_cdp 进程
  - 建议：commander_batch 锁里增加"发现同章旧实例先终止"逻辑，
         或跑批前统一清理
