## 二、军队式树状层级架构

### 2.1 三层指挥体系

```
根（最高指挥）
└── 统帅（OpenManus魔改版，L3全局权限）
    │
    ├── 中层（将军级指挥官，L2受限权限）
    │   ├── 指挥官A：内容创作军
    │   │   └── 管辖：生成卡、老师卡、学生卡
    │   ├── 指挥官B：数据分析军
    │   │   └── 管辖：分析卡、匹配卡
    │   └── 指挥官C：系统运维军
    │       └── 管辖：脚本卡、小助手卡、每天更新卡
    │
    └── 底层（士兵级角色卡，L0/L1权限）
        ├── 分析卡（L0只读）
        ├── 生成卡（L1沙箱）
        ├── 老师卡（L0只读）
        ├── 学生卡（L1沙箱）
        ├── 匹配卡（L0只读）
        ├── 小助手卡（L2受限）
        ├── 每天更新卡（L2受限）
        └── 脚本卡（L1沙箱）
```

### 2.2 军事理论原则

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **集中-分布协同** | 统帅集中决策，各角色卡分布执行 | 统帅选卡→角色卡执行→统帅监督验证 |
| **任务牵引** | 以任务为核心，动态编组 | 根据任务类型自动选择最合适的角色卡 |
| **弹性编组** | 可单角色、可多角色串行/并行 | 单角色调度已实现，多角色待实现 |
| **人在回路** | 关键决策需用户确认 | AskHuman工具，关键节点询问用户 |
| **跨层级直达** | 紧急情况可越级指挥 | 统帅可直接调用任何工具，不经过角色卡 |

### 2.3 角色卡之间的关系

- **平级不沟通**：同层级角色卡之间不直接沟通，只对统帅负责
- **统帅协调**：需要多角色协作时，由统帅拆解任务、分发、回收、组装
- **世界书共享**：所有角色卡共享世界书（通用规则、通气公告、决议台账）
- **权限隔离**：不同权限级别的角色卡只能使用对应权限的工具

## 三、世界书（共享信息空间）

### 3.1 世界书定位

世界书是Blackboard（黑板）模式的实现，作为所有角色卡共享的信息空间，相当于军队的"作战地图"和"指挥日志"。

```
世界书（共享信息空间）
├── 通用规则（8将军共享共识）
│   ├── 控制链架构（MainAgent→角色卡→脚本→输出）
│   ├── 权限分级（L0只读/L1沙箱/L2受限/L3全局）
│   ├── 反刍闭环（任务完成→更新管理员卡→更新运行记录）
│   └── 额度保护策略（粗活外包、深度思考用网页版、知识库本地化）
│
├── 通气公告（新规则/新经验）
│   ├── 新发现的坑和解决方案
│   ├── 新验证通过的流程
│   └── 新升级的脚本版本
│
├── 决议台账（已固化的规则）
│   ├── 角色卡选择规则
│   ├── API分配规则
│   ├── 工具权限规则
│   └── 跑批流程规则
│
└── DeepSeek思考知识库（常驻专家）
    ├── 6大思维模式（经验包，第九章提示词）
    │   ├── 需求分析·3步法
    │   ├── 任务拆解·逐项核对法
    │   ├── 决策判断·对比择优法
    │   ├── 错误处理·根因追踪法
    │   ├── 回复组织·结构化输出法
    │   └── 思维纪律·防重复循环
    ├── 3673条思考过程（可检索，98MB语料）
    └── 105条精选示例（按6大分类查询）
```

### 3.2 世界书使用方式

| 场景 | 使用方式 | 消耗额度？ |
|------|---------|-----------|
| 统帅决策时 | 自动参考世界书通用规则 | ❌ 不消耗 |
| 遇到新问题时 | 检索DeepSeek知识库，参考思考方式 | ❌ 不消耗 |
| 角色卡执行时 | 参考世界书决议台账的固化规则 | ❌ 不消耗 |
| 任务完成后 | 将新经验写入世界书通气公告 | ❌ 不消耗 |
| 需要深度思考时 | 调用3标签网页版（不消耗API额度） | ❌ 不消耗API |

2. **深度思考用网页版**：复杂方案优化 → 3标签网页版，不消耗API
3. **知识库本地化**：DeepSeek思考方式 → 本地检索，不消耗额度
4. **Pro模型省着用**：95次/天，仅用于最高级决策
5. **四模型轮转**：已实现，避免429限流

## 五、飞书远程操控闭环（嘴巴）

### 5.1 闭环流程

```
用户（手机飞书）
    │ 发指令（文字/语音）
    ▼
飞书机器人（WebSocket长连接）
    │ 接收消息，解析指令
    ▼
OpenManus统帅
    │ 理解指令，选择角色卡，分配API
    ▼
角色卡执行（调用工具/API/3标签）
    │ 执行任务，返回结果
    ▼
统帅验证/汇总
    │ 验证结果，汇总输出
    ▼
飞书机器人（推送结果）
    │ 文字/图片/文件
    ▼
用户（手机飞书）
```

## 八、核心设计理念

### 8.1 统帅定位

> **一切的一切都是为了让脚本运行一切。**

- 用户只需给简单指令 → 一级一级层层分包 → 最后找出合适脚本完成合适动作
- MainAgent不亲自逐条操作（额度有限），所有过程都是为了升级脚本
- 最终形成庞大的脚本体系，MainAgent需要动手的越来越少

### 8.2 控制链架构

```
MainAgent（大脑：理解命令/决策/选卡/定节奏）
   ↓ 控制
角色卡（规则执行：按卡内规则调度）
   ↓ 生成/控制
脚本（批量工具：快速执行）
   ↓
输出 → MainAgent 监督/验证/更新
```

- **控制者**：MainAgent控制角色卡 → 角色卡控制脚本
- **监督者**：MainAgent监督角色卡/脚本运行，出错及时纠正
- **更新者**：MainAgent只改两样东西：脚本（补特征词/修bug）和角色卡（记录结论/新规则）

### 8.3 反刍闭环

每个任务完成后：
1. 更新管理员卡（追加任务记录/新规则/新流程）
2. 更新运行记录（`角色卡\运行记录\`）
3. 思考过程蒸馏到`角色卡\蒸馏\`
4. 有可复用新规则 → 蒸馏到对应角色卡
5. 新经验 → 写入世界书通气公告
