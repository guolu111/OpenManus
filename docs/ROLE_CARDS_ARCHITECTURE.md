# 角色卡体系架构设计

> 本文档说明OpenManus统帅如何通过角色卡体系实现多角色协同，参考了业界成熟方案。

## 一、为什么需要角色卡？

单个智能体的问题：
- ❌ 一个人格干所有事，行为不一致
- ❌ 没有权限隔离，容易越权操作
- ❌ 上下文有限，无法同时记住多个领域的专业知识
- ❌ 复杂任务没有分工，效率低

角色卡体系解决：
- ✅ 每个角色有明确的定位和行为规范
- ✅ 基于风险等级的权限隔离（只读/沙箱/全局）
- ✅ 专业知识按角色分类，上下文更聚焦
- ✅ 复杂任务拆解给多个角色协同，效率高

## 二、业界成熟方案参考

### 2.1 Codex CLI 的 Custom Agent 方案（最推荐参考）

每个角色是独立的TOML文件：
```toml
# ~/.codex/agents/reviewer.toml
name = "Code Reviewer"
model = "claude-sonnet-4-5"
sandbox = "read-only"
instructions = """
你是一个代码审查专家，只负责审查代码，不修改代码。
审查时关注：安全性、性能、可维护性、最佳实践。
"""
```

**我们借鉴**：角色卡独立文件，每张卡指定模型、权限、行为指令。

### 2.2 OpenManus 原生多智能体方案

基于 `BaseFlow` 抽象类：
- 规划Agent：拆解任务
- 执行Agent：调用工具
- 验证Agent：校验结果

**我们借鉴**：统帅=规划+验证，角色卡=执行，分工明确。

### 2.3 HermesAgent 的三人小队 + 权限隔离

- 研究员：只读权限，全网溯源和数据收集
- 编码员：沙箱权限，写逻辑跑代码
- 评估员/协调员：全局权限，统筹调度

**我们借鉴**：基于风险等级的权限隔离策略。

### 2.4 Multiple Personas 的 SOUL.md 方案

```
profiles/
├── researcher/
│   └── SOUL.md      # 身份与价值观
├── coder/
│   └── SOUL.md
└── reviewer/
    └── SOUL.md
```

**我们借鉴**：角色卡目录结构，每张卡有完整的身份定义。

## 三、我们的角色卡体系

### 3.1 角色卡清单

| 角色卡 | 定位 | 权限级别 | 适用场景 |
|--------|------|---------|---------|
| **文件夹管理员** | 总管理员/统帅 | 全局 | 文件夹管理、任务调度、反刍闭环 |
| **分析** | 分析师 | 只读+分析 | 文本分析、数据统计、问题诊断 |
| **生成** | 生成器 | 沙箱+生成 | 内容生成、代码编写、方案设计 |
| **老师** | 导师 | 只读+教学 | 知识讲解、教程编写、学习指导 |
| **学生** | 学徒 | 沙箱+学习 | 模仿学习、练习生成、试错验证 |
| **匹配** | 匹配器 | 只读+匹配 | 角色匹配、相似度计算、分类归类 |
| **小助手** | 中转API调度 | 受限+API | API调用、数据搬运、批量处理 |
| **每天更新** | 连载业务 | 沙箱+业务 | 金庸连载跑批、分天版生成 |
| **脚本** | 脚本副将军 | 沙箱+脚本 | 脚本管理、工具注册、代码复用 |

### 3.2 角色卡目录结构

```
角色卡/
├── 文件夹管理员.txt          # 总管理员卡（统帅级）
├── 分析.txt                   # 分析师卡
├── 生成.txt                   # 生成器卡
├── 老师.txt                   # 导师卡
├── 学生.txt                   # 学徒卡
├── 匹配.txt                   # 匹配器卡
├── 小助手.txt                 # 中转API调度卡
├── 每天更新.txt               # 连载业务卡
├── 脚本.txt                   # 脚本副将军卡
├── 世界书/                    # 跨卡共享信息集散地
│   ├── 通用世界书_v3.9.txt
│   └── 数据契约_Schema_v1.0.json
├── 小助手说明/                # 小助手相关文档
│   ├── 小助手使用说明.txt
│   ├── 统一桥接服务_测试报告_v1.0.txt
│   └── 豆包桥接_测试失败记录_待激活.txt
├── 文档/                      # 角色卡设计文档
│   └── 四角色卡v5.0修改方案_四层分开版.txt
└── 蒸馏/                      # 角色卡蒸馏成果
```

### 3.3 世界书：跨卡共享信息集散地

世界书是8张角色卡共享的"会议室"：
- **议事厅**：通用规则讨论
- **通气区**：新规则/新经验公告
- **议政厅**：争议讨论
- **决议台账**：已固化的规则登记

工作流：
```
发现通用规则 → 贴通气区 → 通知统帅 → 固化到将军卡 → 登记决议
```

## 四、统帅调度逻辑

### 4.1 单角色任务流程

```
用户下达任务
    ↓
统帅分析需求（任务类型、复杂度、风险等级）
    ↓
选择合适的角色卡（基于角色定位和适用场景）
    ↓
加载角色卡配置：
  - 系统提示词（角色卡内容）
  - 权限级别（决定可用工具）
  - 模型选择（简单任务用轻量模型，复杂任务用旗舰模型）
    ↓
用该角色卡的身份执行任务
    ↓
执行完成，回到统帅身份
    ↓
汇总结果，返回给用户
    ↓
管理员卡反刍：
  - 更新运行记录
  - 蒸馏可复用经验
  - 同步世界书
```

### 4.2 多角色协同流程

复杂任务可以拆解给多个角色卡：

```
用户：帮我分析鹿鼎记第22章并生成优化方案
    ↓
统帅拆解任务：
  1. 分析卡：分析章节结构、人物、钩子
  2. 生成卡：根据分析结果生成优化方案
  3. 老师卡：审查优化方案，给出教学建议
    ↓
串行执行：分析卡 → 生成卡 → 老师卡
    ↓
统帅汇总三方结果，返回给用户
```

并行执行（适合独立子任务）：
```
用户：帮我同时分析智谱、千问、豆包三个标签的回复质量
    ↓
统帅拆解：3个标签的分析是独立的
    ↓
并行启动3个分析卡实例（分别分析3个标签）
    ↓
汇总3份分析报告，对比总结
```

### 4.3 角色选择决策树

```
任务来了
  ↓
是文件夹管理/任务调度？→ 是 → 文件夹管理员卡
  ↓ 否
是连载跑批业务？→ 是 → 每天更新卡
  ↓ 否
是脚本管理/工具开发？→ 是 → 脚本卡
  ↓ 否
是API调用/数据搬运？→ 是 → 小助手卡
  ↓ 否
是分析/诊断/统计？→ 是 → 分析卡
  ↓ 否
是生成/创作/编写？→ 是 → 生成卡
  ↓ 否
是教学/讲解/指导？→ 是 → 老师卡
  ↓ 否
是匹配/分类/相似度？→ 是 → 匹配卡
  ↓ 否
是学习/模仿/试错？→ 是 → 学生卡
  ↓ 否
默认 → 生成卡（最通用）
```

## 五、权限隔离体系

### 5.1 权限级别定义

| 级别 | 名称 | 可用工具 | 适用角色 |
|------|------|---------|---------|
| L0 | 只读 | 读取文件、搜索、浏览网页 | 分析、匹配、老师 |
| L1 | 沙箱 | L0 + Python执行、代码生成 | 学生、生成、脚本 |
| L2 | 受限 | L1 + API调用、文件编辑（指定目录） | 小助手、每天更新 |
| L3 | 全局 | 所有工具 | 文件夹管理员（统帅） |

### 5.2 工具白名单机制

每张角色卡有自己的工具白名单：
```
分析卡工具白名单：
  - read_file
  - search_web
  - browse
  - python_execute（只读模式）
  ❌ write_file
  ❌ delete_file
  ❌ bash
  ❌ browser_use（可浏览不可操作）
```

### 5.3 风险等级升级机制

- 默认按角色卡权限执行
- 遇到需要更高权限的操作时，统帅临时升级权限（需记录）
- 高风险操作（删除文件、全局bash）必须统帅亲自执行，不能外包给角色卡

## 六、实施路线图

### Phase 1：基础框架（当前）
- ✅ 角色卡文件已就绪（8张业务卡+管理员卡+世界书）
- ✅ 角色卡目录结构已规划
- ⏳ 角色卡注册表（记录每张卡的定位/权限/工具白名单）
- ⏳ 统帅角色选择逻辑（根据任务类型自动选卡）

### Phase 2：单角色调度
- ⏳ 实现角色卡加载器（读取txt→注入系统提示词）
- ⏳ 实现权限隔离（工具白名单/黑名单）
- ⏳ 实现模型路由（不同角色用不同模型）
- ⏳ 测试：用分析卡做文本分析，用生成卡写代码

### Phase 3：多角色协同
- ⏳ 实现任务拆解器（复杂任务→子任务列表）
- ⏳ 实现串行调度（A卡→B卡→C卡）
- ⏳ 实现并行调度（多卡同时执行）
- ⏳ 实现结果汇总器（多卡结果→统一报告）

### Phase 4：自我进化
- ⏳ 角色卡效果评估（哪张卡干哪类活最好）
- ⏳ 自动优化角色卡提示词（根据执行结果迭代）
- ⏳ 新角色卡自动生成（发现新领域需求时自动创建）
- ⏳ 世界书自动更新（跨卡经验自动沉淀）
