【核心职责】
======================================================================
1. 【统一仓库】所有脚本归入一个仓库，按功能分类子文件夹，禁止散落各处。
2. 【注册表】每个固化脚本登记：路径/功能/输入输出/依赖/最近使用，MainAgent查表即用不重写。
3. 【复用优先】写脚本前先查注册表——有现成的直接调用；有的稍改即可；确实没有才新建。
4. 【固化/临时两档】重复率高/要长期用的→固化（_stable 区，登记注册表）；一次性探查/临时→临时区（_tmp，用完即删）。
5. 【统一缓存】脚本中间产物/缓存统一放 仓库\_cache\，不散落。
6. 【分类管理】按功能分大类子文件夹（见下），每个脚本放对类。

【工作铁律】
======================================================================
R-01 写脚本前【必查注册表】：脚本注册表.txt 有没有现成可复用的？有→调用；没有→才新建。
R-02 新脚本【必分类】：生成时直接放对子文件夹，不丢主目录/临时堆。
R-03 分级晋升（金字塔渐进铁律）：**心急吃不了热豆腐——不能一次性固化所有功能，只能在使用过程中逐步逐级晋升。**
  - 同一功能【第1次使用】→ 只做临时脚本（_tmp），跑完即删/保留观察，不固化。
  - 同一功能【第2次重复使用】→ 才允许晋升一级：_tmp → _stable（固化，登记注册表）。
  - 【第3次及以上】→ 继续向上：2-3个 _stable 经常一起用 → 合并 _big；多个 _big 整合 → _super。
  - 规则核心：**没有经过2次实战检验的功能，一律不固化**。防止"假固化"（没用过就固化 = 又造一堆死脚本）。
  - 每次固化必须登记注册表（路径/功能/层级/依赖），并同步更新本卡。
R-04 临时脚本：一次性探查/调试→放 _tmp，任务结束即删，不积压。
R-05 缓存统一：脚本中间产物一律 _cache\，不散落各书目录。
R-06 命名规范：脚本名用功能+场景，如 _gen_fentian_all.py、_hook_scan.py；临时加 _tmp 前缀。
R-07 修改路径：MainAgent（更新者）→ 本卡 → 改脚本 → 重跑 → 验证 → 更新注册表。
R-08 反刍：每次任务结束，登记新脚本/更新注册表/清理 _tmp，回写本卡与运行记录。
R-09 批次分块陷阱（2026-09-02 神雕ch2踩坑）：batch_run.py 的 read_items 对无空行清单会退化为【按行拆】——单日完整原文（多段落）绝不能通过 batch_run 补跑单条，会拆成多条；补跑单条直接用 gcli_helper.qa() 调用（带完整性校验 required 字段，max_tokens 提到 12000 防截断）。
R-10 模块路径铁律（2026-09-02 chapter_verify 踩坑）：脚本 import 桥接模块（gcli_helper/deep_helper）时，必须动态 sys.path 加入 bridges 目录，禁用硬编码绝对路径——BASE 用 os.path.dirname(os.path.abspath(__file__)) 逐级上溯。

======================================================================
- 绝对不能盯住一两个好用的通道。每次任务都要拆分(除非任务非常小，拆不开)。

R-13 音频处理·可复用工具链（v2.3新增·2026-09-02《野子》成功案例）
======================================================================
遇到【音频/视频转字幕、剪切音频、人声分离、伴奏减弱】等任务，先查以下路径：
- 转字幕（中文高质量）：faster-whisper small 本地模型
   模型路径: D:\bat\GitHub\cli\models\faster-whisper-small\（483MB本地）
   调用: WhisperModel(模型目录, device="cpu", compute_type="int8")
   模型下载: HF_ENDPOINT=https://hf-mirror.com + requests流式（hf-mirror可访问，hf.co被墙）
   依赖: pip install faster-whisper ctranslate2（py3.8兼容）
- 剪切音频（精确秒）：ffmpeg
   D:\bat\GitHub\ffmpeg\bin\ffmpeg.exe
   ffmpeg -y -i 输入 -ss 开始 -to 结束 -c copy 输出（剪切）
   ffmpeg -y -i 输入 -acodec pcm_s16le -ar 44100 -ac 2 输出.wav（转wav）
   ffmpeg -y -i 输入 -codec:a libmp3lame -qscale:a 2 输出.mp3（转mp3）
- 人声分离（保人声减伴奏·零下载）：中心声道提取法
   依赖: numpy + soundfile（已装）
   公式: center=(L+R)/2 留人声, side=(L-R)/2 留伴奏, 输出=center+0.33*side
   效果可接受；要求更高才需 demucs/spleeter（demucs需py3.9+，当前3.8不可用）
- 完整案例: 一念永恒小说\脚本仓库\_stable\音频处理_野子成功案例.txt
- 说明：任务完成后抓脚本使用数据丢小助手评估是否固化/合并（R-11）

R-15 脚本归位铁律（v2.4新增·用户2026-09-03强调）
======================================================================
- 【零散落原则】：禁止在仓库根目录或非指定分类下创建任何独立脚本。新脚本必须归位到对应分类。
- 【路径修正】：凡涉及跨模块调用，必须用相对/动态定位（BASE硬编码项目根），严禁 __file__ 裸相对定位（移动后失效）。
- 【归位校验】：新脚本提交前必须通过 core/verify 路径合规检查，否则拒绝入库。
- 【注册表强制更新】：任何脚本创建/移动/重命名/删除，必须同步更新 脚本注册表.txt（路径/功能/层级/依赖）。

R-16 金字塔固化机制（v2.4明确层级晋升）
======================================================================
- L1 临时区(tmp)：任何新脚本初始存放，仅测试/原型。
- L2 功能区(task/core)：同一功能用满2次、验证稳定 → 晋升 core/gen 或 core/verify（登记注册表）。
- L3 核心区：长期运行且多任务依赖 → 固化 core/（禁止随意修改）。
- 降级：连续30天无调用或报错率>10% → 降级 archive/。
- 规则核心：没有经过2次实战检验的功能，一律不固化（防假固化）。

R-18 临时脚本统一归纳机制（v2.6新增·2026-09-03 三通道方案整合）
======================================================================
【职责分工】
- 执行者=脚本卡(副将军·军械库总管): 物理搬运/归档/重命名/合并,拥有 _tmp→_stable 全权操作权
- 决策者=流程总览技能: 价值评估,判断脚本是否复用价值,拥有金字塔等级定级权
- 监督者=省流模式技能: 质量审计,定期扫描仓库清理冗余/过时/冲突脚本

【归纳流程】(临时脚本生成后闭环)
1. 入库: 临时脚本统一存入 _tmp
2. 识别: 流程总览扫描 _tmp,标记标签(功能/频率/重要性); 7天内调用超2次→触发固化预警

R-19 单通道搁置规则（v2.6新增·用户2026-09-03强调）
======================================================================
- 判定: 连续3次请求失败(5xx/连接超时/响应空)或超时(gcli>10s/deep>30s/qwen>60s)→标记[SUSPENDED]
- 搁置: 从可用池剔除,后续请求只在[AVAILABLE]池轮询; 冷却300秒不重试
- 任务挂载: 失败任务封装{ID,Content,Original_Channel,Retry_Count}存入任务栏[WAITING_FOR_RETRY]
- 空闲重试: 并发<2且有Pending任务时,用剩余双通道轮询; 全部SUSPENDED→全局等待60s Ping健康度
- 恢复: 空闲重试成功1次→移除SUSPENDED恢复AVAILABLE
- 原则: 跑不通先搁置下架用双通道跑,问题挂任务栏,空闲重跑(用户决定何时空闲)

- 调用: python 目录索引脚本\_dir_index.py
